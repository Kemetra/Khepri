What Khepri refuses, and why

  • Comparison with an earlier period — not available. Your file covers a single period, so there is no earlier period inside it to compare against.
  • Basket size — not available. Your file has no receipt or invoice number, so there is no way to tell which rows belong to the same sale.
  • Growth drivers — not available. Splitting growth into price and volume needs a quantity for each sale, and the file has none.
  • Sales concentration — not available. The file does not identify products or branches distinctly enough to separate one from another.
  • Basket size — not available. Some rows carry a receipt number and some do not, so this would describe part of your sales as if it described all of them.
  • Growth drivers — withheld. Price and volume effects were calculated, but they do not add up to the total revenue change. Rather than present a split that does not reconcile, it is withheld.

Questions

What does Khepri need from me?
The sales export your point-of-sale system already produces. There is no integration to build and no schema to match first.
What happens when my file cannot answer a question?
The question is refused by name, in the place the answer would have appeared, with the reason and the file change that would make it available.
Can I check a figure against the rows behind it?
Yes. Evidence is reached from the claim it supports rather than from a separate archive.
Do Arabic and English readers get the same thing?
Yes, and it is enforced rather than intended. A missing string fails the build rather than reaching a reader.
Will the same file give the same answer twice?
Yes. Facts are deterministic and versioned, under a stated calculation version.
How do I get access?
Khepri is in private beta with a small number of retail operators. Access is arranged directly, and there is no public sign-up.
