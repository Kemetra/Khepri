# Reporting presentation design package

**Status: draft, awaiting owner approval of the golden sample. Docs only — no product
code changed. Implementation must not begin until the golden sample is approved.**

## Why this package exists

Owner review of the generated HTML, PDF, and Excel outputs on 2026-08-04 found that
they present technical data to a customer: raw metric identifiers, figure and citation
identifiers, unit-kind codes, section states, refusal codes, caveat codes, and full
bundle provenance — all inside the primary report, styled as machine identifiers.

The initial diagnosis was an incomplete wording table. `rendering/wording.py` words
**3 governed metric codes, 2 comparison-mode labels, 5 section headings and 3 chart
descriptions — and 0 refusal reasons and 0 caveats.** That diagnosis was too narrow.
The outputs are **structurally** audit ledgers — ordered by how Khepri computed
things, not by what a reader needs to decide. Translating the identifiers in place
produces a translated technical report.

The fix is two explicitly separated presentation layers.

## The golden sample

Fictional client "Al Rahma Trading Co.", January–July 2026. Every number is invented.

| File | What to look for |
|---|---|
| `khepri-sales-review-sample.html` | Nine business sections, then a Technical Evidence section below a divider |
| `khepri-sales-review-sample.pdf` | 8 pages; business body, then the appendix on a fresh page |
| `khepri-sales-review-sample.xlsx` | 12 sheets: eight business + one Arabic summary, a visible chart-data sheet, then Audit Trail and Provenance |
| `verify_separation.py` | The checks below, runnable |

The workbook was generated by a throwaway script in the session scratchpad, not by
product code. The PDF was rendered by Chromium and passes all four of `pdf.py`'s
publication guards (`%PDF-` header, `%%EOF` trailer, three tagged markers, embedded
font program).

### What makes it "rich" — and the constraint on that

The sample uses **all twelve governed metrics**: the ten in `facts.py:69-78` plus the
two growth effects in `analysis/growth.py:72-73`. The first draft used four, which is
why it read thin — `cost`, `gross_profit`, `gross_margin`, `discount`, `returns` and
`average_selling_price` are all computable today and were reaching the page as raw
identifiers or not at all.

Richness comes from metrics Khepri **already computes**, never from invented analysis.
A golden sample is a promise about the product; inventing a forecast, a customer
segmentation, or a basket-affinity matrix would make the sample a specification for
work nobody approved — the same over-promising, in the opposite direction. The one
metric the sample deliberately does *not* show is comparable-store sales, which is
recorded as a roadmap item instead (see below).

Depth added: per-month margin trend, per-branch revenue/units/margin/change,
discount-and-return leakage as a share of revenue, and seven "what this means"
insight callouts that read the figures against each other rather than restating them.

### Mechanically verified — run it yourself

The separation rule is decidable, so it is checked rather than eyeballed:

```
.venv/Scripts/python.exe docs/reporting/golden-sample/verify_separation.py
```

Current result — every check passes:

| Check | Result |
|---|---|
| Identifiers in 9 business worksheets | **0** |
| Identifiers in HTML business region | **0** |
| Identifiers in audit regions | 47 Excel · 46 HTML |
| Eastern-Arabic numerals | **0** |
| Hidden worksheets | **0** |
| Worksheet names over 31 chars | **0** |
| PDF publication guards | 6/6 pass, 8 pages |

Match identifier *tokens*, not words. An early version of the check flagged "Total
revenue change" because it contains `revenue`, which is also a metric id — a business
name and its identifier usually share a root. The HTML check also strips tags before
matching, because an `id=` anchor is navigation the reader uses and is permitted
(matrix §A.2).

**This script should become a required exit criterion of the implementation slice**,
together with a second test asserting that the business and audit regions *together*
still cover every `bundle.figures`, `bundle.caveats` and section. Reconcile will not
catch a relocation that loses content: both surfaces claim
`sections=bundle.section_ids` unconditionally (`html.py:284`, `excel.py:764`), so
`_reconcile_sections_against_bundle` compares an asserted claim against its own
source. That is exactly why relocation is claim-neutral — and exactly why a
relocation that *drops* something would still reconcile.

### Two recommendations reversed before they shipped

**Hiding the chart-data worksheet.** An earlier draft recommended hiding it so the tab
bar stayed tidy. `excel.py:71-75` already argues against exactly that:

> "It is a visible worksheet, not a hidden one. Hiding numbers that a decision permits
> only conditionally is the wrong direction: an auditor opening the workbook is owed
> every cell in it."

`APP-013` permits a numeric cell in the workbook *conditionally*, and a conditional
permission that hides its own evidence is worse than no permission. The sheet ships
visible.

**Withholding the audit layer at delivery.** See below — the cited evidence turned out
to prove the opposite.

This check should become a test when the implementation slice lands. Match identifier
*tokens*, not words — an early version of the check flagged "Total revenue change"
because it contains the word `revenue`, which is also a metric id. The business name
and the identifier usually share a root; that is expected, not a leak.

## Findings that change scope

1. **The customer-facing catalog is 11 distinct codes, in 13 contexts — not 32.**
   8 section reasons (`GOVERNED_SECTION_REASONS`) + 5 result reasons
   (`facts.py:80-84`), but `required_input_unavailable` and
   `incomplete_transaction_identifiers` appear in **both**, so the distinct union is 11
   and each of those two needs two messages. The **20** `GOVERNED_REASONS` are
   bundle-integrity codes: when one fires **no report is published**, so a customer
   cannot encounter one.

   Earlier sessions summed all three vocabularies to "32". An earlier draft of this
   package corrected that to "13" and *reproduced the same double-counting error*. The
   differentiator survives both corrections; the count did not.

2. **The separation is a pure presentation change.** `reconcile`
   (`bundle.py:1271-1315`) validates the `SurfaceContent` claim and never parses the
   document. No change to the reconcile contract is proposed or required. **This is the
   one load-bearing claim that survived external review unchanged.**

3. **Caveat wording is mandatory and complete, not incremental.** `bundle.py:1324-1325`
   requires claimed and bundle caveat sets to be *equal*. An unworded caveat is a
   reconcile failure. **All 12 codes are worded in §D.4** — 9 in `facts.py:86-94`, 2 in
   `bundle.py:148,163`, 1 in `analysis/growth.py:84`. An earlier draft worded one and
   deferred eleven, which contradicted this very finding.

4. **The business metric-name table must be complete at import.** `worded()`
   (`wording.py:149-151`) raises on a missing code by design — "a fallback would ship it
   quietly" — and a `KeyError` in a renderer is caught as `REASON_SURFACE_FAILED`
   (`bundle.py:1213-1219`), so an incomplete table means **no report**, not an ugly
   label. Guard it with an import-time key-set assertion in the style of
   `wording.py:120-122`.

5. **Excel caps worksheet names at 31 characters**, which leaves a 21-character budget
   once the bilingual suffix is added. Found by an `InvalidWorksheetName` crash while
   regenerating the sample. `Discounts and Returns` sits exactly at the limit.
   `verify_separation.py` now asserts it.

## Delivery: business report always, audit evidence on request

**Owner decision, 2026-08-04.** The business report is the product. The audit
evidence is optional *to the customer*.

Tier A content is generated for every report, unconditionally: `REQUIRED_SURFACES` is
compared for exact equality in **seven** places, so a bundle producing fewer than
three surfaces returns `REASON_MISSING_SURFACE` and is an *incomplete bundle* — no
report at all (`bundle.py:1222`). **Do not implement optionality by skipping
generation.**

"Optional" is a **render variant of each surface**, not a delivery filter.

> **Corrected after external review.** An earlier version of this section claimed the
> audit layer could be withheld by a delivery-time filter, citing
> `delivery_persistence.py:239`'s `if surface in found` guard as evidence that the
> delivery layer "already tolerates reading a subset."
>
> **That reading was wrong.** Line 239 is a corruption detector feeding a rejector —
> its consumer at `delivery_persistence.py:346-350` raises `DeliveryCorrupted` on any
> delivery that does not name every required surface. The package used six equality
> checks to argue generation must always happen, then assumed the seventh path was
> permissive. It is not.

So the audit content is a **region inside each surface**, and which region a
customer's copy includes is decided before the surface is stored. All three surfaces
are stored and read whole; every equality gate passes; no delivery contract changes.
IA §B.1 carries the two remaining routes and the recommendation.

The business report names its reference and points to the evidence once, in the
colophon, and carries no identifier anywhere else.

## The largest unpriced work item: test migration

Not addressed by this package and flagged by external review as the omission most
likely to have surfaced the other errors sooner.

**19 test files carry ~170 references** to the structure this design relocates
(`figure_id`, `citation_id`, `data-reason`, `unit_kind`, `<code>`), concentrated in:

| File | References |
|---|---|
| `tests/test_rra006_bundle_sections.py` | 45 |
| `tests/test_rra006_bundle.py` | 19 |
| `tests/test_rra006_bundle_section_reconcile.py` | 18 |
| `tests/test_rra006_excel_charts.py` | 17 |
| `tests/test_rra006_charts.py` | 17 |

`tests/test_rra006_excel_charts.py` addresses the chart-data worksheet **by name** in
eleven places, so the sheet's name and visibility are both test-pinned.

Two consequences the implementation slice must plan for: this is likely the largest
single chunk of work in Phase 1, larger than the wording tables; and the tests
currently *pin the ledger structure as correct*, so migrating them is an act of
deciding what the new contract is, not mechanical find-and-replace.

**Checked, and it is not a problem: the benchmark asserts nothing about rendered
content.** `_require_whole_report` (`benchmark_trial.py:161-165`) checks only that a
*complete* bundle names every required surface:

```python
def _require_whole_report(surfaces: tuple[str, ...], complete: bool) -> None:
    if not complete:
        return
    if surfaces != REQUIRED_SURFACES:
        raise ValueError("A complete bundle names every required surface.")
```

It never inspects figures, caveats, sections, or the disclosure, and it takes the
renderers as a port (`benchmark_trial.py:74`). So the presentation change touches the
benchmark's assertions not at all — which follows from §B.1's rule anyway, since all
three surfaces are still produced. Answered by reading, because the benchmark is one of
the two required CI checks that exist in no workflow file and cannot be run locally.

## Scope boundary

Docs only. No `src/` edits, no registry edits, no new decision record — and after
external review, **no governance dependency is known**. The one candidate found (hiding
the chart-data worksheet, which would have required an `APP-013` amendment) was
withdrawn rather than pursued; `APP-013` pins `KHEPRI-DEC-005` by document digest, so
editing the governed document fails `khepri-gov validate`.

`verify_separation.py` is a verification script for the sample, not product code. It
imports nothing from `khepri`.
