App shell & navigation

Structure

Outer page #E9E3DA, 26px padding. App frame: max-width 1620px, radius 16, border #DED7CC, shadow 0 40px 80px -52px rgba(18,28,38,.55). Grid: 238px / 1fr.

  • Sidebar: navy gradient #101C26 → #0B1017, logo lockup, 8 nav items, quote card pinned to bottom (margin-top: auto).
  • Topbar: white, 1px bottom border, 12px/24px padding — search pill, language switch, notification bell, user chip.
  • Content column: #FBF9F6, contains an optional hero band then a padded card grid.
Rules
  • Nav item: 46px min-height, 10px radius, 13px gap, 18px icon. Active = gold left bar (inset 3px 0 0 #C9A45C) + linear-gradient(90deg, rgba(201,164,92,.26), rgba(201,164,92,.02)) and gold icon stroke.
  • Hover on inactive: rgba(255,255,255,.06), label to #DFE3E7.
  • Upload and Review both mark New Analysis active; Insights and Report both mark Insights active.
  • Breadcrumbs live in the hero band, not the topbar. Processing and Report use a single back link instead.
  • Primary page action sits top-right of the hero band (Insights) or in a bottom action row (Upload, Review).
  • The prototype nav strip below the topbar is a demo affordance only — omit it in production.

Elevation

08

Icon usage

One family, drawn from the supplied Khepri icon sheets: geometric, open, stroke-only. viewBox 0 0 24 24, fill: none, stroke 1.4–1.8 (1.6 default), round joins, no filled shapes except the logo's sun disc and status dots.

  • Sizes: 14 (inline meta) · 16–17 (buttons, links) · 18 (nav, banners) · 19–21 (KPI tiles) · 22 (footer) · 30–54 (empty states, dropzone).
  • Stroke color: #C9A45C active nav and brand moments, #A8823A in gold tiles, #4A5560/#6B7580 neutral UI, status ink inside status components, currentColor in nav labels.
  • Never two icon weights in one row; never an icon without a text label except the bell and chevrons.
  • Egyptian motifs (sun disc, pyramid, horizon rings) appear only in the logo lockup, the sidebar quote card and report chrome — never as UI affordances.

Arabic / RTL behavior

  • Language is a single dir switch on the app root — dir="rtl" plus lang="ar". The whole shell mirrors: rail moves to the right, chevrons and arrows flip, breadcrumbs and steppers reverse.
  • All spacing and alignment already use logical properties: margin-inline-start/end, padding-inline, border-inline-start, inset-inline-end, text-align: start/end. Do not introduce left/right properties.
  • Type: Noto Sans Arabic for Arabic UI at 400/500/600/700; line-height rises to 1.8–1.85 for Arabic body copy. Arabic does not use the serif display face — use Noto Sans Arabic 600 at the same sizes.
  • Numerals, currency, percentages, dates and file sizes stay Western/LTR inside RTL text; wrap each in a dir="ltr" span so $482M and +18% do not reorder.
  • Hero artwork is not mirrored — the composition is symmetrical. Only the scrim gradient flips (use to inline-end or a [dir="rtl"] override) and object-position mirrors to 38% 46% so the monument stays on the copy-free side.
  • Charts: bar and line axes mirror (time flows right → left); the donut keeps its rotation, legend mirrors. Progress bars fill from the inline start.
  • Mixed-direction rows (English filenames in an Arabic UI) get unicode-bidi: plaintext on the label.

Implementation notes
  1. Build the shell first as a layout route: SideNav + TopBar + content outlet. All six screens are content-only; none may alter shell chrome.
  2. Expose the tokens in section 03–05 as CSS custom properties on :root and use them everywhere; no ad-hoc hex values in components.
  3. Author every offset with logical properties from day one — RTL is a dir flip, not a second stylesheet.
  4. Charts are hand-authored SVG at fixed viewBoxes with width: 100%. If you swap in a chart library, match the palette, the 1px #EFE9E0 gridlines, mono axis labels and serif value labels exactly.
  5. Status is data-driven: one status enum (success | warning | error | info | pending) should drive badge, row tint, meter fill and icon together. Never hardcode a tint on a row.
  6. The hero artwork is a supplied asset — crop only. No CSS or SVG recreation of the monument, sun, water or sky under any circumstance.
  7. Every hero container needs its solid ground color so headlines are legible before the image decodes; ship compressed derivatives (section 09).
  8. Serif face is for display and numerals only; never set UI labels, table cells or buttons in serif.
  9. Keep one primary action per screen. Processing has none — it is read-only until complete.
  10. Animations are limited to three keyframes: khSpin 900ms linear, khBar 1.6s ease-in-out, khPulse 1.5s ease-in-out. Transitions are 140ms on background and color only. Respect prefers-reduced-motion by freezing all three.
  11. Accessibility: label the language switch as a control with aria-pressed; give every progress element role="progressbar" with value attributes; announce Processing task changes via an aria-live="polite" region; focus ring is the gold border plus a 2px rgba(201,164,92,.35) outline offset 2px.
  12. The prototype nav strip and screen-switch props in Khepri Product UI are demo scaffolding — drop them and wire real routes.
