## 3. The three gaps — MEASURED

1. **Isolation covered three surfaces of nine.** §Verification requires it "on every surface".
2. **The print surface had no parity coverage, and it renders governed prose.**
   `decision_print.html.j2:19` is `<html lang="{{ language }}" dir="{{ direction }}">`, line 38
   sets `data-language`, and it includes the same `_decision_cards.html.j2` and
   `_decision_sections.html.j2` partials the screen uses. Driven over HTTP it answers **200 with
   `dir="rtl"`** in Arabic — the surface worked, and no test had ever asked it.
3. **Nothing asserted the extent.** Seven files each tested their own surface, so no test failed
   when a new surface shipped without parity or isolation. That is how gap 2 reached `main`, and it
   is the gap that would otherwise have produced a gap 4.

**Gap 3 is the slice's subject.** Gaps 1 and 2 are its first two findings.

## 4. Parity over every render mode — MEASURED

Produced by `tests/test_d110_parity.py`, 13 tests. Both languages × both render modes, driven over
the real route.

**The seam matters.** `render_decisions` takes four positional arguments and hardcodes
`decision.html.j2` (`shell_decisions.py:884`), so it cannot reach the print surface at all. The only
path that renders `decision_print.html.j2` is `?print=1` on the language-parameterised prefix
(`FR-047`). A parity extent over *every* surface therefore has to be driven over HTTP, reusing
`test_d108_print.py::_shell` rather than rebuilding the wiring.

**RTL is asserted as parity evidence only** — that the page declares its own direction. `RCA-008`
§Exclusions leaves the layout programme to `U1-05`/`U1-06`/`U1-07`, so no viewport, snapshot, image
diff or accessibility scan appears here.

## 5. Cross-organization isolation over every mode — MEASURED

Produced by `tests/test_d110_isolation.py`, 6 tests.

Driven as the **other** member asking for the owner's run at the owner's address. A request that
changes the address while staying the owner tests routing, not isolation. Absence and denial are
compared as a real attacker would compare them: same actor, same address shape, one run that exists
elsewhere and one that exists nowhere — a foreign member learning that a run *exists* but is denied
is a cross-organization leak in the shape of a status code.

## 6. How each extent was made able to fail — MEASURED

| Mutant | Observed |
|---|---|
| Drop `SECTION_CONCENTRATION` from the derivation, **before** the independent pin | **12 passed** — the assertion was a tautology |
| The same mutant **after** pinning to `SECTION_COPY` | **FAILS** `test_the_section_copy_agrees_with_the_section_constants` |
| Remove the Arabic heading for a section — a real parity defect | **8 failed**, including the parity extent |
| Isolation test asks as the *owner* instead of the foreigner | **2 failed** — the tests discriminate rather than passing blanketly |

**The tautology is the finding worth recording.** `expected_roster()` and `SURFACES` both derived
from `_section_keys()`, so they moved in lockstep and the comparison restated itself: removing a
whole section from the product's roster passed every test. A derived assertion compared against
itself passes every mutant.

The fix is an **independent** source. `SECTION_COPY` is the template's own bilingual copy,
maintained separately because it carries governed prose, so it disagrees when one side drifts — and
asserting `SECTION_COPY["en"].keys() == SECTION_COPY["ar"].keys()` puts `FR-171` parity over section
headings at its source, where a heading added in one language and not the other fails immediately.

**The third mutant is why the isolation tests are believable.** Asking as the owner makes the
assertion fail, which proves the foreign case's pass is a real refusal and not a blanket error that
would swallow both.

roster is the union of both sources, and the asymmetry is correct.
