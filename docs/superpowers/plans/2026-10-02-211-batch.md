### 2. Issuance's own advisory lock, exercised at run time (from `#210`)

**Still applies, in part.** `R4-07` (#224) already made the blocking assertion deterministic:
`test_the_purge_blocks_on_a_held_issuance_lock` reads `pg_locks` for a waiting purge. But its
holder took a hand-written `pg_advisory_xact_lock` on the test's own connection. Issuance's
acquisition in `SqlInvitationStore.add_invitation` was therefore never exercised. Replacing that
call with `pass` left all ten PostgreSQL tests green on `main` (`10 passed`).

**Change.** `_paused_issuer` runs `InvitationService.issue` unmodified. An `after_flush` session
event, on a factory that only the issuer uses, pauses `add_invitation`'s own transaction after its
insert. The purge then meets whatever lock production took. The different-address control uses
the same issuer. `_hold_lock_and_write`, `_insert_invitation_row` and `_Row` are removed. The
module stays marked `concurrency`, so CI's `require_concurrency_tests.py` refuses a skip.

**Not RED,** because both locks exist on `main`. The RED-equivalent is the surviving mutant above.

### 3. The axis unit stays inside the canvas (A12, recorded by #643)

**Still applies.** The unit is start-anchored at the start edge (`axis_unit_x` is `0` or `640`).
Measured with `getBoundingClientRect` on `main`, the printed Arabic unit reaches past the canvas
by **0.594 px** (`نصيب`) and **0.653 px** (`عملة`). The English unit, and the web report in both
languages, measure 0.000.

**Authority.** `RRA-015` FR-183 and FR-188 (registry `state: active`). §Scope names `charts.py`'s
axis and label geometry and its RTL mirroring.

**Change (next commit).** `charts.AXIS_UNIT_INSET` moves the anchor inside the start edge, through
`_mirror`, so it is the same distance in from the start edge in each language.

**Tests (RED at `11ac802`).**

- `test_rra015_chart_label_band.py` measures the axis unit's inline edges as well. The printed
  report fails with `clipped sideways: نصيب`, `عملة`, `نصيب`. The margin is about 0.09 px over the
  0.5 px tolerance, measured on Windows Chromium. The Linux engine's metrics differ, so the
  view-model case below is the stable guard. The web cases already measured 0.000 with the unit
  included, so they carry no marker.
- `test_the_axis_unit_is_inset_from_the_start_edge` (three kinds) fails on
  `Decimal('0') < Decimal('0.0000')`.

### 4. The #629 addendum (2026-09-30)

- **(a) Arabic start-edge clipping: fixed by #643.** The curve's last Arabic label measures 0.000
  px past the left edge on the web report at 1440 px and at 390 px with 200% text, and in print.
  #643's sideways check covers it in both languages.
- **(b) The top marker at y = 0: not fixed, and not label geometry.** The marker's fill is not
  clipped at the top: its rectangle spans y 0 to 8, and it measures 0.000 past the top edge on
  all three surfaces. Its halving is sideways. That is the end dot `charts._rank` accepts by
  design. What does reach past the top is half of the curve's 2-unit stroke (`.chart__curve`,
  `stroke-width: 2`) at its highest point, whose y is 0. `getBoundingClientRect` excludes stroke,
  so this is stated from the geometry rather than measured. Clearing it would mean headroom above
  the plot. Every mark would then move, and `test_rra006_charts` pins the canvas as the plot plus
  the two bands. That is plot geometry, not label geometry, so it stays open on #629.
