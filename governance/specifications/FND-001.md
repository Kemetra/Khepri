# FND-001: Minimal Governance Kernel

## Outcome

Keep Khepri's governed artifact graph valid with one registry and one local/CI validation command.

## Requirements

- Keep `governance/registry.yaml` authoritative for artifact type, identity, state, document,
  dependencies, and supersession.
- Admit only decision, family, and specification artifacts.
- Admit only active and retired states.
- Require unique identifiers and Markdown documents that exist inside the repository.
- Require known, unique, acyclic dependencies with no self-dependency.
- Require each specification to depend on exactly one family.
- Reject an active artifact that depends on a retired artifact.
- Require a named successor to be a different active artifact of the same type.
- Expose validation through `uv run khepri-gov validate`.
- Run validation, Ruff, and pytest on pull requests and `main`.

## Exclusions

This specification does not authorize product behavior, infrastructure, deployment, spending, or
changes to privacy and data boundaries. It does not create an approval ledger or delegate owner
authority to automation.

## Verification

```text
uv run khepri-gov validate
uv run ruff check .
uv run pytest
```

The validator test suite covers valid metadata plus schema, field, vocabulary, identity, path,
dependency, family, and supersession failures.
