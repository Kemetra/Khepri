# FND-001: Governance Kernel and Repository Controls

## Outcome

Establish a clean Khepri repository whose governance can be validated locally and in CI
before product application code is admitted.

## Requirements

- Publish the constitution, named authority, successor/reference decision, and FND boundary.
- Keep authoritative YAML registries for authorities, decisions, families, and
  specifications.
- Enforce closed lifecycle states, unique identifiers, known active owners, existing
  document paths, valid family relationships, valid and acyclic dependencies, and mandatory
  approval evidence.
- Expose validation through `uv run khepri-gov validate`.
- Use Python 3.13, PyYAML, pytest, Ruff, and a committed `uv.lock`.
- Run validation, Ruff, and pytest on pull requests and `main`.
- Protect `main` with pull requests, required checks, resolved conversations, blocked
  force-pushes and deletions, and squash merges only.

## Exclusions

This specification does not authorize product application code, customer functionality,
domain behavior, infrastructure services, new product families, or a runtime stack for any
future product.

## Verification

A clean clone must pass:

```text
uv sync --frozen
uv run khepri-gov validate
uv run ruff check .
uv run pytest
```

The test suite includes a valid graph plus duplicate identifiers, unknown owners, closed
state violations, missing files and approvals, bad dependencies, dependency cycles, and
unknown or inactive family assignments.

Identity, state, family, owner, dependencies, and approval evidence are authoritative in
`governance/registries/specifications.yaml`.
