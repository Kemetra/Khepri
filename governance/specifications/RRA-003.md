# RRA-003: Retail Data Profiling and Admissibility

## Outcome

The system produces a content-minimized profile and an explicit retail column mapping, then
admits only datasets that can support governed retail facts.

## Requirements

- Profile schema, row count, null rate, distinctness, numeric ranges, date coverage, and
  parse-quality findings without exposing raw values in operational logs.
- Detect likely personal-data columns and exclude them from narrative and reporting inputs.
- Map source columns to governed retail semantics with confidence, evidence, and a safe display
  label.
- Require deterministic confirmation rules for revenue, units, transaction identifiers, dates,
  products, categories, stores, channels, cost, discounts, and returns as applicable.
- Distinguish required, optional, unavailable, ambiguous, and conflicting mappings.
- Reject datasets with no admissible time field, no answerable core retail measure, irreconcilable
  types, or unresolved ambiguous mappings needed by the requested report.
- Preserve the accepted profile and mapping version as provenance for the fact package.

## Exclusions

Free-form semantic analysis, arbitrary customer formulas, opaque automatic guessing, and raw-row
transfer to an LLM are not authorized.

## Verification

Tests cover golden schemas, type conflicts, missing columns, ambiguous mappings, personal-data
exclusion, fail-closed admissibility, and deterministic reruns.

This specification is draft and does not authorize product implementation.
