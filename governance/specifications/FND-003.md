# FND-003: Delegated Approval Records

> Retired by the schema-version-2 migration. Its delegation machinery is no longer active.

## Outcome

The validator admits an approval performed by a named delegate under a recorded delegation, and
rejects every delegated approval that misattributes its approver, exceeds its recorded scope, relies
on a delegation that is absent, malformed, expired, or revoked, or reaches the reserved set defined
in Article VIII.

## Requirements

- Require every record in the authorities registry to declare `human` as a boolean, and reject a
  registry in which any record omits it. A delegate is a record with `human: false`.
- Admit a delegation record under `governance/delegations/` carrying a schema version, an
  identifier, the delegate it grants to, the human authority granting it, the instruction verbatim,
  the date and session in which the instruction was given, a scope, an expiry date, and a revocation
  flag. Reject a record that omits any of them or names an unknown, inactive, or non-human delegate.
- Admit two scope forms and no others: an enumerated list of artifact identifiers, or the token
  covering every artifact outside the reserved set. Reject any other form, including a prefix, a
  registry name, or a family name.
- Admit an approval block whose approver is a delegate only when it names the delegation record it
  acts under, and reject a delegated approval block that names a human authority as its approver.
- Reject a package whose approval names a human authority but whose evidence is a delegation record,
  and a package whose approval names a delegate but whose evidence is a human evidence reference.
- Record the delegate's identifier, not the granting authority's, in every registry entry a
  delegated package materialises, and reject a materialisation that records the human's.
- Reject a delegated approval whose delegation record is expired at the package's approval date,
  carries a revocation flag, or was recorded for a session that the package does not name when the
  scope is a session scope.
- Reject a delegated approval that transitions an artifact outside the delegation's enumerated
  scope.
- Reject a delegated approval that reaches the reserved set: any artifact whose document is the
  constitution, the authorities registry, or a delegation record, and any decision whose acceptance
  would alter the reserved set.
- Reject a change to the constitution, the authorities registry, or any delegation record in a
  commit that also carries a delegated approval, so that reserved-set immutability under delegation
  is enforced at the file level and not only at the artifact level.
- Keep validation fail-closed: an unrecognised scope form, an unresolvable delegation reference, an
  ambiguous approver, or a partially supplied delegation record blocks, and never degrades to a
  warning.

## Exclusions

This specification does not authorize any product application code, any change to a product family
or its specifications, and no judgement about which delegations ought to be granted. It does not
grant the delegate any authority: a delegation exists only when a human authority instructs one into
existence, and this specification only describes how such an instruction is recorded and checked. It
adds no lifecycle state to any registry. It does not make a delegation record cryptographically
verifiable, and it does not claim that the repository can detect a fabricated one; Article VIII
already states that a delegation record is an attestation. It does not restore commit signing, which
remains the only mechanism that would make approval attribution cryptographic rather than declared.

## Verification

The test suite must cover: an authorities registry missing `human` on any record; a delegate that is
unknown, inactive, or marked human; each required delegation-record field absent in turn; both
admitted scope forms and at least three rejected forms; a delegated approval naming a human
approver; a human approval carrying a delegation reference; a materialised registry entry recording
the human instead of the delegate; an expired delegation; a revoked delegation; a session-scoped
delegation used by a package naming a different session; an artifact outside an enumerated scope;
each reserved-set artifact class in turn; and a commit changing a reserved-set file alongside a
delegated approval.

A clean clone must continue to pass `uv run khepri-gov validate`, `uv run ruff check .`, and
`uv run pytest`, and every existing approved package `APP-001` through `APP-010` must remain valid
without modification, since none of them is delegated.

This specification is draft and does not authorize product implementation.
