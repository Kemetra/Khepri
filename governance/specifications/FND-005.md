# FND-005: CI Test-Completeness for Dependency-Gated Markers

**Status:** PROPOSED. This document governs nothing until the sole owner merges it to `main`
(`governance/CONSTITUTION.md` §II). It was drafted by automation, which "checks facts and
consistency; it does not approve changes or act as a separate authority" (§I).

**Family:** `FND`.
**Depends on:** `FND-001`.

---

## Outcome

Make the `pytest` run `FND-001` requires on pull requests and `main` fail when a test marked
`browser` did not actually run, rather than report green because the dependency it needs is absent.

## Why this document exists

`FND-001` requires the repository to "Run validation, Ruff, and pytest on pull requests and
`main`." That run happens: `.github/workflows/governance.yml:87` is a bare `uv run pytest`.

What it does not do is run every test. Measured at `64190f7` on 2026-09-19:

| Fact | Measurement |
|---|---|
| Tests carrying `@pytest.mark.browser` | **236** |
| Where they live | 128 `test_r811_shell_accessibility.py`, 43 `test_r807_shell_quality.py`, 22 `test_r810_shell_responsive_rtl.py`, 18 `test_rca011_shell_font_load.py`, 12 `test_r812_shell_visual_regression.py`, 7 `test_rra_journey_browser.py`, 2 each `test_rra_journey_review.py`, `test_rra006_pdf_surface.py`, `test_rra006_pdf_sections.py` |
| Chromium install step in the `pytest` job | **none** |
| Result in CI | all 236 skip; the job reports green |
| Result locally with the pinned Chromium | **236 passed, 0 skipped, 323s** |

So every browser-measured contract in the repository — the `RCA-010` `FR-200` accessibility floors
computed in a real browser, `FR-204`'s visual evidence, `RCA-011`'s proof that the shell's typeface
is actually fetched over the wire, and the `RRA` journey and PDF surfaces — is verified only on a
developer machine that happens to have Chromium installed.

**This is not a defect in any of those tests.** Each skips rather than silently passing, which is
the honest behaviour. The gap is that a skip and a pass are indistinguishable in a green check, and
`FND-001`'s control is read from the check.

## The reading this extends

`FND-001` says *run pytest*, and CI runs pytest. A strict reading is satisfied today, and this
document does not claim otherwise. The narrower claim is the one the repository already acts on:

> a governed control that silently deselects tests for a missing dependency is not the control
> `FND-001` names.

`.github/scripts/require_concurrency_tests.py`, wired at `governance.yml:94-95`, already argues exactly
this for the `concurrency` marker — "a concurrency test that skips reports green, and green reads as
proved" — and refuses two conditions: any marked test skipped, and the marker matching nothing at
all, "because 'these tests do not exist yet' and 'these tests were silently disabled' are
indistinguishable from outside."

That gate traces to **no governed artifact**. It is correct, and it is ungoverned prose. This
document is therefore the first to govern CI test-completeness rather than an extension of an
existing authority, and it governs one marker.

## Scope

- `.github/workflows/governance.yml` — the `pytest` job installs the pinned Chromium before
  `uv run pytest`, and runs the guard below after it.
- `.github/scripts/require_browser_tests.py` — new, mirroring `require_concurrency_tests.py`.

`.github/` is named by no other active specification. `RCA-010` §Scope reaches `tests/` but
excludes every `src/khepri/runtime/*.py` module and does not name `.github/`; no `RCA` or `RRA`
document names CI at all.

## Requirements

- Install Chromium in the `pytest` job from the repository's existing pin. `uv.lock` constrains
  `playwright` to `>=1.61,<2`, so `uv run playwright install chromium` resolves the browser the
  lockfile already fixes. The workflow names no Chromium revision of its own; `image.yml:111-116`
  reads the revision out of `browsers.json` for the descriptor and remains the only place a
  revision is transcribed.
- Fail the job when any test marked `browser` was skipped.
- Fail the job when the `browser` marker matches no test at all, on the same fail-closed reading the
  concurrency guard states: a renamed or deleted marker and an unwritten one are indistinguishable
  from outside, and only the first is a regression.
- Run the guard after the full suite, so it re-runs only the marked subset.

## Exclusions

This specification does not authorize product behavior, infrastructure, deployment, spending, or
changes to privacy and data boundaries. It does not create an approval ledger or delegate owner
authority to automation. Specifically:

- **No test file is changed.** Not one of the 236 is edited, re-marked, or moved. All 236 pass
  today against the pinned Chromium; this document adds no test and weakens none.
- **No stylesheet, template, or `src/` file is changed.** Nothing here reaches product code.
- **The `local_stack` marker is deliberately excluded.** It has the same structural hole — a
  marker that skips when `docker-compose.local.yml` is not running — and closing it requires
  standing a stack up in CI, which is a different change with a different cost. Naming it here
  records that it was seen and declined, not overlooked.
- **The `concurrency` guard is not reopened.** It keeps working as written; this document notes
  that it is ungoverned and does not retroactively govern it.
- **No judgement about the `RCA-010` `FR-200` and `FR-204` clauses whose subjects are absent.**
  Two recorded absences — the `role="status"` clause and §16.4's refusal reference — have no
  reachable subject today and carry unmarked, parametrized skips in `test_r811:517`. Those tests
  are **not** `browser`-marked, so `-m browser` deselects them and the guard never sees them. That
  is verified, not assumed: the marked subset reports 0 skipped.

## Cost, stated plainly

The marked subset takes **323 seconds** locally (5m23s). CI adds that to every pull request and
every push to `main`, plus the Chromium download on a cold cache. That is a real and recurring
cost, and it buys 236 contracts moving from "verified on one developer's machine" to "verified by
the gate."

## Verification

```text
uv run khepri-gov validate
uv run ruff check .
uv run pytest
```

An implementation slice additionally proves:

- The guard fails when a `browser`-marked test skips. Proven by running it in an environment with
  no Chromium and asserting a non-zero exit, not by reading the code.
- The guard fails when the marker matches nothing, proven the same way against a marker name that
  selects no test.
- The guard passes when all marked tests run, which is the state measured above.
- The workflow names no Chromium revision, asserted statically over `governance.yml`.

Every new file scores 10.00 in the required server-side CodeScene Code Health Review and no tracked
hotspot declines.
