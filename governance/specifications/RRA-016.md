# RRA-016: Beta Journey Visual Language Implementation Authority

**Status:** PROPOSED. This document governs nothing until the sole owner merges it to `main`
(`governance/CONSTITUTION.md` §II). It was drafted by automation, which "checks facts and
consistency; it does not approve changes or act as a separate authority" (§I).

## Outcome

The private-beta journey surfaces at `/beta/{language}/{step}` — upload, review, processing, the
report step, and the terminal states — realize the approved Khepri visual language the commercial
shell already carries: the owner's §16.5 palette declared in the journey's own stylesheet, the
approved Product UI handoff's journey compositions (screens 02 Upload, 03 Review, 04 Processing),
and the approved hero artwork where the handoff places it, served from the journey's own address.

Every step, state, action, figure, refusal and governed word on those surfaces is still `RRA-002`'s,
`RRA-003`'s, `RRA-006`'s and `RRA-009`'s. This specification adds presentation over what already
exists, and adds no capability.

## Why this artifact exists

The owner supplied the final Product UI handoff (`docs/ui/design_handoff_khepri_product_ui/`) on
2026-09-22 and its §4 maps screens 02–04 onto the `/beta` journey. Its shell strategy (§4) restyles
the journey and the workspace "inside their current architecture so they share one visual
language". `RCA-010` and `RCA-012` carried the workspace half. No active specification can carry
the journey half:

- `RRA-010` §Requirements is a closed list of **defect corrections** — accessibility, responsive,
  bilingual and right-to-left, semantic-state treatment, token consumption, focus, and recovery.
  Its token clause "authorizes reading a value from a name; it does not authorize choosing a
  value."
- `RRA-010` §Exclusions: "Cross-surface visual consistency is not this authority's to deliver."
- `RRA-010` §Exclusions also refuses "a new route, address, or asset filename; a change to the asset
  allowlist", and `RCA-012` §Exclusions assigns the journey half of the hero artwork to "a separate
  RRA-family artifact not drafted here".

Moving the journey onto the §16.5 values chooses values, and it is visual consistency across
surfaces. This is the receiving authority, in the shape `RCA-010` received the shell stylesheets.

## Successor reading

`RRA-010` stays `active` and unedited. This is clause-level successor authority, not whole-artifact
retirement; no artifact names `superseded_by`.

1. **`RRA-010` §Requirements, "it does not authorize choosing a value".** Unchanged as a reading of
   `RRA-010`. This specification authorizes choosing exactly one set of values: the master
   specification §16.5 palette, declared in `journey.css` (`FR-220`). No other value choice is
   authorized here either.
2. **`RRA-010` §Exclusions, cross-surface visual consistency.** Delivered here, **by restatement, not
   by sharing**: the journey declares the same §16.5 values in its own stylesheet. The exclusion's
   companion rule — no dependency on a value, class or asset owned by the shell — is unchanged and
   binds this specification too (`FR-222`).
3. **`RRA-010` §Exclusions, new asset filename and allowlist change.** Succeeded for the two hero
   derivatives only, as allowlist entries in `src/khepri/rra/journey/routes.py` (`FR-227`). No
   other filename, route or allowlist change is authorized.
4. **Everything else in `RRA-010` stands**, for slices under this document as for its own: surface
   identity, capability neutrality and domain silence (its §Scope tests 1–3); terminal-state
   cross-session indistinguishability; the recovery-affordance rule; its privacy, runtime and
   bilingual invariants; and its named test modules.

## Scope

This specification governs presentation over surfaces that already exist:

- `src/khepri/rra/journey/assets/journey.css` — tokens and rules.
- `src/khepri/rra/journey/templates/` — presentation markup and ARIA state only.
- `src/khepri/rra/journey/assets/*.js` — presentation behavior only: focus, ARIA state, progressive
  disclosure. No new data read and no new request.
- Presentation-only copy keys in `src/khepri/rra/journey/copy.py` — a control's, region's or
  artwork's accessible name, with the module's import-time parity discipline.
- `src/khepri/rra/journey/routes.py` — **the asset allowlist entries for the two hero derivatives
  only** (`FR-227`). No route, handler, state, read, or other allowlist entry.
- `tests/` — focused palette, composition, responsive, right-to-left, accessibility, hero-load and
  visual-evidence tests over the journey surfaces, extending the journey test modules `RRA-010`
  names. No test under another specification's Verification is weakened or deleted.

**Not in scope:** `shell.css`, `shell-components.css` and every shell or runtime module; the `RRA`
report render surfaces, `rendering/templates/`, `report.css`, `report.print.css` and the charts
(`RRA-006`, `RRA-012`, `RRA-015`); the rendered report bundle, which the report step reaches
rather than contains; `src/khepri/rra/journey/hero.py` and its derivatives, which are `RCA-012`'s
and are consumed, not changed; every journey route, handler, state machine and store; and the
landing surface.

## Requirements

Numbering continues from the highest requirement on `main`, `RCA-001` `FR-219`.

### Palette

- **FR-220**: The journey declares the master specification §16.5 palette as custom properties in
  `journey.css`, and its rules consume those properties. The values are §16.5's exactly; a journey
  value that differs from its §16.5 row is a defect. The composition is §16.5's: a dark navigation
  or chrome region carries the navy, and content stays on the ivory and sand surfaces. **This is not
  a dark theme**, and no theme control is added.
- **FR-221**: A status triplet is paint over a state the surface already states in words or shape.
  No journey state is distinguished by colour alone, and a governed refusal never carries error
  paint (`RRA-010` §Requirements, unchanged).
- **FR-222**: The journey names no custom property, class, or asset whose authority sits with the
  shell, and no shell stylesheet reaches a `/beta` page. There is no shared token layer: the same
  values are restated, not referenced (`RCA-010` `FR-201`, unrelaxed).

### Composition

- **FR-223**: Screens 02 Upload, 03 Review and 04 Processing take the handoff's composition —
  hierarchy, density, spacing rhythm, typography scale, component geometry and state presentation —
  over the elements each step already renders. An element the handoff draws that the journey does
  not already render is **omitted**, not added: no stepper step, figure, file tile, promo copy,
  search, notification or account control the runtime does not serve.
- **FR-224**: The typeface stays the vendored Noto Sans Arabic at the scale `RRA-010`'s type-scale
  tests already pin. The handoff's serif display face is not introduced.
- **FR-225**: Motion stays `RRA-010`'s: `prefers-reduced-motion` guards every animation and fills a
  progress track rather than freezing it. No new animation is added for decoration.
- **FR-226**: The responsive and right-to-left posture holds at 1440, 1024 and 390 in both
  languages: logical properties only, no page-level horizontal overflow, 44px targets on the element
  a pointer lands on, and every existing destination and download on the report step unchanged.

### Hero artwork on the journey

- **FR-227**: The journey serves the two approved hero derivatives `RCA-012` already audits
  (`khepri-hero.jpg`, `khepri-hero.webp`) by exact name through its existing asset allowlist, from
  `/beta/assets/`. Their bytes are read through `src/khepri/rra/journey/hero.py`, whose import-time
  digest check is unchanged, so a drifted derivative is refused rather than served. The supplied
  2.4 MB PNG is not served.
- **FR-228**: The artwork is placed only where the handoff §6 table places it on a journey screen —
  02 as its right-rail card, 03 and 04 as bands — cropped by `object-fit` and `object-position` only,
  never filtered, recoloured, rotated or mirrored; right-to-left mirrors the focal point, not the
  image. Copy on the artwork sits on the handoff's wash inside its solid stop, and a surface that
  fails to load the artwork remains legible and complete.
- **FR-229**: The artwork is decorative and carries no governed meaning. Its alternative text comes
  from `journey/copy.py` in both languages, not from a template, and no journey stylesheet names a
  `/app` address (`RCA-012` `FR-217` and `RCA-011` `FR-208`, mirrored).

## Exclusions

This specification authorizes none of the following, and a slice claiming it does is outside its
specification within the meaning of Constitution IV:

- Any new route, address, step, state, workflow phase, capability, request, data read, or backend
  behavior; any allowlist entry beyond `FR-227`'s two.
- Any change to a figure, refusal, caveat, reason, or governed report word. Those are `RRA-004`'s,
  `RRA-006`'s and `RRA-009`'s.
- The `RRA-010` journey-adoption reading
  (`docs/superpowers/plans/2026-09-03-rra010-journey-adoption-reading.md`). Whether a `/beta` page
  may load the `RRA-012` component stylesheet stays undecided, and no slice under this document acts
  as though any option were chosen.
- The report render surfaces and their stylesheets, including the handoff's screen 06 report
  composition. Restyling them needs its own authority naming those files.
- Any shared token layer, shell asset, or commercial-shell context on a `/beta` page.
- Any new package, dependency, font, icon family, external reference, CI workflow, or weakening of
  the shipped Content Security Policy.
- Any telemetry, persistence, retention change, or retained presentation state.

## Verification

Every slice under this specification proves, with focused tests:

- The journey's declared palette equals the master specification §16.5 rows — asserted against
  §16.5 as the independent source, never against `shell.css`, since comparing one copy to the other
  proves nothing — and an unlisted colour literal in `journey.css` still fails.
- No journey stylesheet or template names a shell custom property, class, asset, or `/app` address,
  and no shell-owned asset reaches a `/beta` page; the existing `RRA-010` guards stay passing.
- Surface identity, capability neutrality and domain silence: no route, handler, state, read, or
  allowlist entry changed beyond `FR-227`, by static scope evidence.
- In a real browser, both languages at 1440, 1024 and 390: no page-level horizontal overflow, 44px
  targets, visible focus on every tab stop, contrast computed rather than asserted, reduced motion
  filling rather than freezing, and text scaling to 200% without loss.
- Terminal-state cross-session indistinguishability is unchanged.
- For the hero: the derivatives are fetched over a real HTTP origin from `/beta/assets/` with a 200
  and their audited digests, an unknown name is refused, the PNG is not reachable, the focal point
  mirrors under right-to-left while the image does not, and the alternative text is present in both
  languages.

The normal repository gates pass: `uv run khepri-gov validate`, `uv run ruff check .`, and
`uv run pytest`. Every new file scores 10.00 in the required server-side CodeScene Code Health
Review and no tracked hotspot declines.

## Implementation preconditions

1. `RRA-016` is `active` in `governance/registry.yaml`, and `RRA-010` remains `active`.
2. A slice identifies which of palette (`FR-220`–`FR-222`), composition (`FR-223`–`FR-226`) or hero
   (`FR-227`–`FR-229`) it implements. The hero is its own slice, after the palette.
3. Slices are small and independently verifiable, as Constitution IV requires, and do not widen this
   specification, its privacy boundary, its runtime boundary, or its data use.

Identity, state, document, dependencies, and supersession are authoritative in
`governance/registry.yaml`.
