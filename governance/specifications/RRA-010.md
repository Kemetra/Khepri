# RRA-010: Beta Journey Presentation Maintenance

## Outcome

The existing private-beta journey surfaces at `/beta/{language}/{step}` are maintainable as
presentation: their accessibility, responsive behavior, bilingual and right-to-left rendering,
semantic-state treatment, and focus and navigation semantics may be corrected in small verifiable
slices, without adding capability, without crossing the commercial boundary, and without depending
on a surface this specification does not govern.

`RCA-002` excludes the beta journey's routes, templates, and assets and assigns that surface to
`RRA`. This specification is the receiving authority for that assignment, covering the surface
`RRA-006` does not: `RRA-006` governs one report bundle and its web, PDF, and Excel render targets,
while the journey's intake, review, and progress steps precede a bundle and are not an output format
of one.

## Scope

This specification governs presentation of surfaces that already exist:

- `src/khepri/rra/journey/templates/` — presentation markup and ARIA state.
- `src/khepri/rra/journey/assets/journey.css`.
- `src/khepri/rra/journey/assets/*.js` — presentation behavior only: focus, ARIA state, progressive
  disclosure.
- Presentation-only copy keys in `src/khepri/rra/journey/copy.py` — keys naming a control, a state,
  or an affordance.
- `tests/test_rra_journey_accessibility.py`, `tests/test_rra_journey_browser.py`, and
  `tests/test_rra_journey_pages.py` — extending assertions.

`src/khepri/rra/journey/assets/shell.css` and `shell-components.css` are **outside this scope**.
They sit in the journey's asset directory and are the shell's: `shell.html.j2` is their sole linking
template, no `/beta` page loads them, and ownership follows the linking template rather than the
folder.

Three tests bound every change, and a change failing any one is outside this specification however
small it looks:

1. **Surface identity.** The change alters how an existing journey surface is presented. It adds no
   surface, step, workflow state, or route.
2. **Capability neutrality.** The change adds no capability, route, workflow state, or backend
   behavior. **Neutrality is measured against the runtime and domain, not against the rendered
   page.** A presentation change MAY make an already-authorized destination or outcome reachable. It
   MUST NOT create a destination, action, or outcome the runtime does not already serve.
3. **Domain silence.** The change reads no new data, computes nothing, persists nothing, and sends
   nothing new anywhere.

Test 2 is stated against the runtime because a rendered-page reading would forbid the corrections
this specification exists for: a skip link that becomes reachable, a scroll container that gains a
tab stop, and a `/beta`-local recovery affordance each add a rendered action while adding no
capability. Measured against the runtime, a link to an already-routed address passes and a control
invoking something the runtime does not serve fails, whatever it looks like.

## Requirements

- Correct accessibility defects on an existing journey surface: programmatic state for a visible
  state the surface already conveys, accessible names, landmark and heading structure, focus
  visibility, and keyboard reachability of content already reachable by pointer.
- Correct responsive defects at supported viewports without introducing a new breakpoint policy: no
  page-level horizontal overflow, and wide content scrolling inside its own container.
- Correct bilingual and right-to-left presentation defects, preserving `RRA-006`'s parity
  obligation: logical properties only, explicit direction for a script run whose direction is not
  the page's, and locale-formatted values.
- Present a semantic state the system already computes with a treatment that matches its meaning. A
  governed refusal MUST NOT be presented with the treatment reserved for a transport or system
  error. The refusal's own text, reason, and evidence are unchanged.
- Consume design token values declared within this specification's governed scope in place of
  equivalent literals, where the token and the literal are the same value or the journey's own token
  declaration documents the collapse. This authorizes reading a value from a name; it does not
  authorize choosing a value. A journey rule MUST NOT resolve a custom property whose sole
  declaration is in a shell-owned asset; where a value must exist for the journey to consume it,
  that value is declared in the journey's own stylesheet, which is where the authority to declare it
  also sits.
- Correct focus and navigation semantics: one skip-link mechanism, correct tab order, and visible
  focus on every tab stop including scroll containers. Consolidating two journey-internal mechanisms
  is authorized; adopting a shell-owned mechanism as the target is not. Where the journey and the
  shell each hold a mechanism, the journey settles on one of its own, restated in its own files.
- Add a recovery affordance to a terminal journey state only where the destination is an existing
  `/beta`-local address that existing runtime authority already serves. A recovery affordance MUST
  be identical in wording, destination, and presence across every collapsed terminal cause, so that
  cross-session indistinguishability is preserved.

## Exclusions

This specification authorizes none of the following, and a slice claiming it does is outside its
specification within the meaning of Constitution IV:

- A new workflow state, step, or journey phase.
- A new route, address, or asset filename; a change to the asset allowlist.
- Any new business capability, and any new runtime or domain capability — a destination, action, or
  outcome the runtime does not already serve. Making an already-served destination reachable is not
  a new capability.
- Any calculation, re-derivation, re-rounding, or re-formatting of an authoritative figure.
- Any new data collection, field, telemetry event, or persistence.
- Organization identity, name, slug, or any commercial-shell context inside `/beta`, and any link or
  navigation into the commercial prefix. Shell-to-journey frame continuity is outside this
  specification.
- Any commercial workspace behavior, membership, role, or invitation semantics.
- Any dependency on a presentation value or asset owned by a surface outside this specification's
  governed scope. Naming a custom property, class, or file whose authority sits with the shell is
  outside this specification even when the resulting pixels would match. Cross-surface visual
  consistency is not this authority's to deliver.
- New report semantics, report content, citation behavior, or refusal content. Presentation of an
  existing refusal is authorized; what a refusal says is `RRA-009`'s.
- The report colophon wording and any other governed report copy. `src/khepri/rra/rendering/html.py`
  is the report renderer and its bilingual catalogue is `RRA-009`'s; a defect there is fixed under
  `RRA-009`.
- Any retention, expiry, or deletion behavior, or any presentation implying a retention guarantee
  the system does not make.
- Public signup, durable history, sharing, comments, or export of anything not already exported.
- Arbitrary remapping, semantic re-interpretation, or any change to admissibility.
- Any API surface change, request or response shape, or status code.
- Any backend, domain, service, or persistence change presented as a UI change. A template that
  begins reading a value the view model did not previously supply is a domain change.

## Invariants

### Privacy, isolation, and security

- `RRA` session isolation and the opaque-owner boundary are unchanged. Presentation gains no
  identifier.
- Operational telemetry remains content-free. No presentation change emits customer content.
- Deletion and expiry guarantees are unchanged, including cross-session indistinguishability: the
  collapsed terminal causes MUST remain indistinguishable by copy, status code, page identity, or
  navigation state.
- The content security policy is not weakened. No inline style or inline script is introduced.
- No customer content, filename, or raw value enters markup that did not carry it.

### Bilingual, right-to-left, and accessibility

- Arabic and English remain equal surfaces with equivalent state, actions, and error text.
- Copy parity stays enforced at import, so a missing key fails the build rather than the visitor.
  Customer-facing strings stay in the copy modules and are never authored in JavaScript.
- Stylesheets contain no physical directional CSS properties.
- Interactive targets meet the minimum target size the existing journey tests enforce, applied to
  the element itself rather than a padded wrapper, in both languages at every supported viewport.
- `prefers-reduced-motion` continues to guard animation and to fill rather than freeze a progress
  track.

### Runtime

- Server-rendered FastAPI and Jinja2 with bundled CSS and minimal bundled JavaScript. No
  single-page-application framework, no Node frontend, no client build step.
- No external fonts, content delivery networks, analytics, or runtime assets. Typefaces remain
  package data verified against their digest manifest.
- No new dependency.

## Verification

A slice under this specification:

- extends the existing journey accessibility and browser tests rather than replacing them, asserting
  each new invariant in both languages and at every supported viewport already parametrized;
- asserts the presence of programmatic state and its absence where it does not belong, so an
  active-state assertion cannot pass on a page that marks every item;
- asserts the refusal-versus-error distinction as a rendered property rather than a class name, so
  the assertion survives a rename;
- re-asserts the no-physical-directional-property invariant over any stylesheet it edits;
- measures rather than assumes any change that could alter layout at the narrowest supported
  viewport;
- replaces, rather than removes, the protection given by any assertion it must change. Where an
  existing assertion greps stylesheet text for a rule, its replacement asserts the computed property
  on a rendered page, which cannot pass against a stylesheet the page does not load.

Two existing assertions encode this specification's own boundary and are not weakened by it: that no
journey page links into the commercial prefix, and that no shell stylesheet reaches a `/beta` page.

The second of those currently names one filename, `shell-components.css`, while this specification
excludes both shell-owned stylesheets from its Scope. **The first slice under this specification MUST
widen that assertion to reject every shell-owned asset on a `/beta` page, `shell.css` included,
before relying on it.** Until it is widened it does not fail closed on the dependency this
specification treats as load-bearing, and `shell.css` is the more consequential of the two: it
declares the tokens, so a journey template linking it would make shell-declared custom properties
resolve on `/beta` — the exact cross-surface dependency the Exclusions forbid. A guard that permits
the more dangerous half of a boundary is not a guard for that boundary.
