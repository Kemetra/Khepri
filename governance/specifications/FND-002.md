# FND-002: Governed Lifecycle Transitions

> Retired by the schema-version-2 migration. Its lifecycle machinery is no longer active.

## Outcome

An approval package can perform every lifecycle transition the registries define, including
supersession and retirement, and the validator enforces a closed set of legal transitions with
traceable linkage between the superseding artifact and the one it replaces.

## Requirements

- Admit a closed set of transitions per registry, and reject every transition outside it:
  - decisions: `proposed` to `accepted`, `proposed` to `rejected`, `accepted` to `superseded`;
  - families: `proposed` to `active`, `active` to `retired`;
  - specifications: `draft` to `approved`, `approved` to `implemented`, `implemented` to `verified`,
    and any approved-or-later state to `retired`.
- Require every transition that ends an artifact's authority to name, in the same package entry, the
  approval reference it supersedes, and reject the entry when that reference is absent, unknown, or
  not itself approved.
- Require a superseding artifact to be named where one exists, and reject a package that ends an
  artifact's authority without either a named successor or an explicit recorded reason.
- Record supersession in the authoritative registry, not only in prose: a decision that has been
  superseded carries the identifier of the decision that superseded it, and the validator rejects a
  `superseded` state without that linkage.
- Reject a linkage that names an unknown artifact, an artifact in the wrong registry, an artifact
  that is not itself approved-or-later, or the artifact itself.
- Preserve the approval evidence of a superseded or retired artifact unchanged, so that supersession
  never rewrites prior authority.
- Keep validation fail-closed: an unrecognized transition, an unresolvable linkage, or a partially
  supplied entry blocks, and never degrades to a warning.

## Exclusions

This specification does not authorize any product application code, any change to a product family
or its specifications, and no substantive judgement about which artifacts ought to be superseded. It
adds no new lifecycle state to any registry: every state named above is already defined. It does not
grant automation the ability to approve, propose, or decide a supersession; it only allows an
approval package that a named authority has approved to record one.

## Verification

The test suite must cover, for each registry: every admitted transition; a rejected transition
outside the closed set; a supersession entry missing its superseded approval reference; a
supersession entry naming an approval that is not approved; a `superseded` registry state with no
linkage; linkage naming an unknown artifact, a cross-registry artifact, and the artifact itself;
preservation of the superseded artifact's original approval fields; and a package that is otherwise
valid failing closed on a partially supplied entry.

A clean clone must continue to pass `uv run khepri-gov validate`, `uv run ruff check .`, and
`uv run pytest`, and the existing approved packages `APP-001` through `APP-006` must remain valid
without modification.

This specification is draft and does not authorize product implementation.
