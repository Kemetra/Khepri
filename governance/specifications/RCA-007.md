# RCA-007: Semantic-View Runtime Composition

## Outcome

An organization-scoped semantic-view request reaches a real projection: the runtime binds
`RRA-014`'s projection to `RCA-006`'s orchestration by reading the published fact package a
completed analysis run already names and rebuilding that run's governed bundle, so a request that
today refuses for an incompatible source shape returns the view its definition admits.

## Why this artifact exists

`RCA-006` §Scope governs no runtime wiring, and `SV1-04` resolved that question against building an
adapter under it. `SV1-08` then measured what the deferral costs and found it larger than a missing
binding. Composed by hand with the real authorization door, the real workspace store, the real
`SemanticQueryActions` and the real `project` -- no test double anywhere --
every request for a published view returns `ViewRefusal('incompatible source shape')`:
`SemanticQueryActions` loads `AnalysisRun` rows, `project` admits a `RenderableBundle`, and the two
do not meet. The binding is therefore a *bundle construction*, and `SV1-08`'s ledger records both
the end-to-end latency baseline and `SV1-07`'s composition property as NOT EXERCISED until it
exists.

Two boundaries have to move for that, not one, which is why this is a new specification rather than
an edit to `RCA-006`:

1. **An organization-scoped package read.** An `AnalysisRun` names its package only by
   `package_digest` and `package_version`. Every package read that exists today is *session*-scoped
   -- `SessionScope` requires a `session_id`, and `FactPackageService.get_session_package` is a
   live-session call. A historical run read in organization scope has no session, so no path from
   that run to its package exists.
2. **The composition root itself**, which `RCA-006` §Scope excludes by its own sentence. Editing
   that sentence to carve out one exception would blur a boundary this specification can instead
   state cleanly, leaving `RCA-006` true as written.

## Scope

- `src/khepri/runtime/semantic_view_adapter.py` -- the future composition boundary that satisfies
  `RRA-014`'s projection protocol over organization-scoped runs.
- The organization-scoped published-package read this composition requires, added to the existing
  `RRA-004` package repository surface as a read-only method.
- `tests/` -- independent contract tests for that boundary.

`src/khepri/runtime/` is the admitted home because it is already the layer that may know both
packages: `runtime/workspace_recording.py` states that `R7-01` §3 forbids either package importing
the other and that runtime is "the one place that may know" both, and
`runtime/run_quality.py` already rebuilds a report bundle from a stored package inside that layer.

No route, template, shell asset, public API, migration, cache, background job, renderer, schema
change, or new persisted column is governed. No existing workspace file changes except the package
repository gaining the read named above.

## Composition flow

```text
RCA-006 orchestration: actor + organization -> opaque scope -> AnalysisRun rows
RCA-007 adapter:       run -> organization-scoped published package record
                            -> rebuild_fact_package(record.document)   [reconstructs the package]
                            -> digest + version-triple check, fail closed on either
                            -> ReportBundle.of(package)                [RUNS RRA-004's derivation]
RRA-014 projection:    definition lookup + validation + no-calculation projection
Result:                the view's own refusal, empty outcome, or projection, unchanged
```

`runtime/run_quality.py` is the precedent for the middle three steps, including the digest
self-check. Its docstring calls the rebuild "a *read* of a published package" -- but that phrase
describes what the module publishes, not what the constructor executes, and the distinction is this
specification's central question.

## The open question this specification cannot settle by itself

**`ReportBundle.of(package)` is not an inert read.** `KHEPRI-DEC-032` measured it: the constructor
calls `family.derive(package)` (`bundle.py:1638`) and `concentration.curve_series(package)`
(`bundle.py:1728`) as it assembles. Every existing caller is admitted on a ground that does not
extend here:

- `KHEPRI-DEC-032` admits the two package-scoped catalog routes because *"it prohibits a catalog
  surface from publishing a figure it computed itself"*, and measured that *"no `value` field, no
  rendered text, and no figure reaches any catalog response."* `report_api.py` states the same
  boundary in its own words: *"A route here that returned a figure would be an `RRA-006` surface."*
- `runtime/run_quality.py` publishes no figure either; it reads which sections answered, carried a
  caveat, or refused.
- `KHEPRI-DEC-032` says plainly: **"This decision authorizes no new surface, figure, or
  telemetry."**

A semantic view *does* publish figures -- values, versions, caveats and evidence are the whole
point of a projection. **The adapter this specification names would therefore be the first path in
the codebase that executes `ReportBundle.of`'s derivation and publishes the resulting figures.**
`KHEPRI-DEC-032`'s admission ground does not reach it, and that decision recorded the contrary
reading rather than dismissing it: if `RRA-011`:204's Exclusion protects *determinism* -- that a
governed figure is computed once, in one place, under one version triple -- rather than *display*,
then re-running the families at semantic-view read time is the re-derivation it forbids, and
`RRA-014` `FR-138` forbids a view arithmetic of its own besides.

**The position this specification takes, with its counter-argument stated.** Determinism is
protected by proof rather than by avoidance. The package is immutable and digest-checked before use;
`family.derive` is a function of that package under a pinned version triple; so a rebuild under an
unchanged digest and an unchanged triple produces what the delivered surfaces produced. `FR-153`
and `FR-157` below require both to match before any figure is published, and a further check
requires repeated projections of one run to be byte-identical. A view therefore repeats a value
produced under the delivered semantics and never announces one produced under new ones.

**What is not claimed.** No test here compares a projected figure against a *delivered surface*.
The surfaces are rendered artifacts -- HTML, PDF, Excel -- and no store holds the figures behind
them in a form a test can read back; `KHEPRI-DEC-032`'s condition-4 evidence compared against an
oracle derived independently from source rows, not against a stored surface. The guarantee offered
is stability under an unchanged package and unchanged versions, which is weaker than surface
equality and is the strongest thing the storage architecture presently supports. A reader who wants
surface equality wants a persisted projection, which is the alternative below.

**The counter-argument.** Under a determinism reading, "computed once" means once, and a proof of
stability is not the same as not recomputing. `FR-153` and `FR-157` answer the two failure modes
that reading names -- a document that drifted from its digest, and a version triple that moved after
delivery -- and both stop the path rather than publishing under changed semantics. What they cannot
answer is the reading itself: if the Exclusion protects the *act* of computing rather than the
*integrity* of what is published, no check makes a second derivation a first one. That reading is
coherent. It is not adopted here because it would make `RRA-014`'s eight published views
unreachable by any path the storage architecture admits -- no store holds a `ReportBundle` --
which is the same unsatisfiability `KHEPRI-DEC-032` point 3 found. If the owner prefers it, the
consequence is not a smaller adapter but a persisted projection, an `RRA-004`/`RRA-006` change
`KHEPRI-DEC-032` already named as the alternative, and this specification is closed rather than
narrowed.

**This question is the owner's, and merging this document is the ruling.** It is recorded as a
recommendation carrying its own counter-argument, following `KHEPRI-DEC-032`'s form.

## Requirements

- **FR-151**: The adapter reads a completed analysis run's published fact package only through the
  requesting organization's opaque scope; a run in another scope, a run with no derived package, and
  an absent package are indistinguishable to the caller and all yield `RCA-006` `FR-146`'s uniform
  content-free unavailable outcome.
- **FR-152**: The bundle is rebuilt from the stored package document and from nothing else. The
  adapter itself performs no arithmetic, aggregation, ranking, or raw-row access and adds no metric,
  dimension, caveat, or evidence value the package does not state; the derivation `ReportBundle.of`
  executes is the governed one `RRA-004` already defines, run under the package's own pinned version
  triple and never re-parameterized here.
- **FR-153**: The rebuilt package's digest is checked against the digest the stored record names,
  and a mismatch fails closed as an unavailable outcome rather than projecting a package the record
  does not vouch for.
- **FR-154**: The adapter satisfies `RRA-014`'s projection protocol structurally and returns its
  outcome unchanged; `khepri.rca` continues to import no concrete `khepri.rra` implementation, and
  the binding exists only in the composition root.
- **FR-155**: The composition adds no database row, object, artifact, cache, preference, history
  entry, tombstone, or deletion evidence, and no new audit or product-telemetry event, counter,
  access record, or content-bearing log; `RCA-006` `FR-148` and `FR-149` hold across the composed
  path exactly as they hold across its halves.
- **FR-156**: The composition property and the end-to-end latency and query-shape baseline are
  measured over the shipped composition rather than a test double, and the two tests that today
  assert the adapter's absence are updated to assert its behavior.
- **FR-157**: The version triple the run recorded at delivery -- `package_version`,
  `formula_version`, and the package's own mapping version -- is compared against the rebuilt
  package's, and any difference yields the unavailable outcome rather than a projection. A figure
  published here is therefore produced under the same governed versions the delivered surface was
  produced under, and a triple that moved after delivery stops the path instead of quietly
  republishing under new semantics.
- **FR-158**: The adapter serves no route and no HTTP response. It returns a projection to
  `RCA-006`'s orchestration in process; any surface that presents one is a later specification's,
  and `report_api.py`'s boundary -- a figure-returning route is an `RRA-006` surface -- is untouched
  by this document.

## Exclusions

This specification authorizes no route, surface, template, or public API; no calculation, formula,
or projection semantics, all of which remain `RRA-014`'s; no persistence schema change, migration,
or new stored column; no cache, pre-aggregation, or materialized view; no retention, telemetry, or
audit record; no cross-organization access; no sharing or export; no raw-row access; and no edits to
`RCA-001`, `RCA-005`, `RCA-006`, or `RRA-014` source paths beyond the single read-only package
lookup its Scope names.

## Retention, privacy, and telemetry

Unchanged from `RCA-006`. The composed query is derived at read time and retains nothing. The
package read is a read; it writes no access record and no log line naming a view, a run, or a
result. The adapter holds no bundle beyond the request that built it.

## Invariants

- `RCA-001` remains the canonical authorization checkpoint, and it runs before the package read.
- `RCA-006` remains the sole orchestration boundary; the adapter is called by it through the
  protocol and never calls it.
- `RRA-014` remains the sole authority for definition lookup, validation, projection, and refusal.
- `RRA-004`'s package remains the only numerical source. The adapter computes nothing of its own;
  the only derivation on the path is `ReportBundle.of`'s, governed by `RRA-004` and pinned to the
  package's own version triple.
- A figure this path publishes is produced under the version triple the run recorded at delivery, or
  the request is unavailable.
- Unavailable conditions stay uniform, content-free, and byte-identical across the composed path.
- A digest that does not match its record is an unavailable outcome, never a projected result.

## Verification

- A real two-organization request proves a run outside the requester's opaque scope yields the same
  content-free unavailable outcome as an absent run within it.
- A run with no derived package and a run whose package record is absent each yield an outcome
  byte-identical to the cross-scope one.
- A tampered stored document whose rebuild does not match its recorded digest yields the unavailable
  outcome and no projection.
- A completed run in the requester's own organization returns an admitted projection whose values,
  versions, caveats, and evidence equal the package's own, proving the adapter added nothing.
- A write-count assertion spans every injected store and proves the composed request writes zero
  records; an audit and telemetry absence assertion proves it emits neither event type, counter,
  access record, nor content-bearing log.
- A static import-boundary assertion proves `khepri.rca` still imports no concrete RRA
  implementation and that the binding appears only in the composition root.
- `tests/test_sv107_boundary_evidence.py` and `tests/test_sv108_query_baseline.py` are updated:
  each today asserts the adapter's absence and must fail until it is replaced by the exercised
  property, and `SV1-08`'s ledger gains the end-to-end distribution it currently records as NOT
  EXERCISED.
- A run whose recorded `package_version` or `formula_version` differs from the rebuilt package's
  yields the unavailable outcome and no projection -- `FR-157`, the evidence on which this
  specification's reading of `RRA-011`:204 rests.
- Repeated projections of one run return byte-identical figures, so the rebuild is stable and not a
  fresh answer each time it is asked.
- A static assertion proves the adapter is reachable from no route and returns no HTTP response.
- Every new file scores 10.00 in the required CodeScene Code Health Review.

1. `RCA-001`, `RCA-005`, `RCA-006`, `RRA-004`, and `RRA-014` are active in
